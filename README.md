# MaiWill（麦意）

MaiWill 是一个以 MaiBot 为主体、由单一 LLM 意志长会话统筹自主能力的插件项目。

MaiWill 按可分发插件开发，使用原版 MaiBot 已公开的插件接口；安装和升级不要求修改宿主源码、打补丁或替换宿主文件。

它不替换 MaiBot 的聊天流程。正常聊天仍由 MaiBot 的 Planner、Replyer、工具系统和人格配置负责；MaiWill 在后台维护一个长期逻辑意志会话，让麦麦自己决定是否学习、使用手机、写日记、整理记忆或休息。

## 为什么另起一个项目

旧的麦生活逐渐形成了许多彼此独立的定时器、状态服务和内部数据结构。那些功能可以继续使用，但它们不适合作为新的核心：每增加一种活动，就会增加一套调度和提示词链路，插件自己的状态也容易与 MaiBot 的聊天和长期记忆分开。

MaiWill 采用另一种边界：

- MaiBot 保留聊天、人格、消息发送、工具注册和长期记忆的主流程。
- MaiWill 维护一个长期逻辑意志会话和负责恢复它的运行时；一个会话统一调用所有自主能力。
- 自主模型调用的 token 记账和体力恢复由代码负责；调用结束后按实际 usage 扣减，体力余额是模型安排休息的成本信号。
- 手机、日记、兴趣记录和记忆整理都是能力，不各自拥有一套自主调度器。
- LLM 在同一会话中决定下一步做什么；能力只负责执行决定并返回结果。
- 学到的内容通过统一记忆接口回到 MaiBot，普通聊天使用 MaiBot 原有的召回路径。

## 设计目标

1. **聊天保持原样**：MaiWill 不扫描或总结普通聊天流。聊天模型只有在确实产生好奇或知识缺口时，才可主动记录一条兴趣记忆；常规对话仍由 MaiBot 负责。
2. **意志会话为主导**：插件启用后持续自主探索；麦麦决定何时行动、何时休息，连接断开时恢复同一逻辑会话。
3. **能力可扩展**：新增日记、手机、复盘或其他活动时，只需增加能力适配器，不再新增一套调度器。
4. **共享学习和长期记忆**：聊天期间由麦麦主动记录的兴趣、手机见闻和反思结果，都可以经过整理写入 A_Memorix。
5. **可恢复和可解释**：意志决定、能力执行、休息和记忆同步都有稳定 ID 和状态，重载后可以继续或明确放弃未完成任务。
6. **长会话持续恢复**：一次活动没有固定步数上限。正常情况下模型通过 `rest` 自行决定休息时长，最长 12 小时；无停止请求时错误地选择 `finish` 会转成默认 1 小时的自主等待，之后继续探索。连接、进程等意外中断时按指数退避恢复，默认最大间隔 10 分钟且可配置。
7. **成本由代码核算**：按模型实际 token 用量扣减 MaiWill 体力；余额允许为负，模型看到透支后可自行选择休息。

## 第一版范围

- 统一意志会话：事件唤醒、观察、决策、工具执行、反思、断连恢复和休息。
- 资源预算：按实际自主 token 用量扣减体力，设置体力上限和恢复速度。
- 聊天兴趣记录：正常聊天模型在确实好奇时调用记录工具，生成待研究记忆并通知同一个意志会话；不做独立聊天扫描。
- 记忆检索和记忆写入适配：把学习结果交给 MaiBot 的长期记忆系统。
- 日记能力：由麦麦自行决定是否写一篇日记，日记正文仍作为麦麦自己的生活记录保存。
- 手机能力：插件内 ADB 适配固定连接配置的专属 Android IP:端口，可读取控件树、点击、滑动、输入、启动 App、执行设备 shell/ADB 子命令、通过 `adb pull/push` 传输设备文件并将截图保存到插件数据目录；最近生成的截图会临时附加到下一次图文决策请求，Base64 不写入持久会话历史。设备内操作面向用户请求和具体自主目标开放；不能改选其他 ADB 设备或控制 ADB 主机。
- 主动回到聊天：需要开口时调用 MaiBot 的主动任务接口，由 MaiBot 完成正常聊天；当前已在插件中实现，目标只限当前上下文里的显式兴趣记录聊天流。

## 明确不做的事情

- 不重写 MaiBot 的 Planner、Replyer 或消息协议。
- 不在插件内复制一套长期知识库并要求聊天同时查询两套系统。
- 不为手机、日记或兴趣研究分别创建常驻调度循环。
- 不把学习描述成模型权重训练；学习结果是可检索的记忆、经验和表达观察。
- 不把旧麦生活的全部模块搬进来。只迁移经验证有价值的能力实现。

## 当前状态

最新源码和安装包为 **0.1.36**。补齐意志决策的 JSON Schema、能力调用字段和输出约定，兼容完整 JSON 代码块与开头 BOM；无效决策会明确报告 JSON 语法位置或字段错误，并在会话详情保留不含响应原文的诊断。校验通过前不执行能力或确认用户消息，连续三次失败仍保留队列并退避。保留 0.1.35 的 `recent_interests` 初始化修复，以及手机瞬移拖拽、动作后截图和方向滚动功能。安装包为 `dist/maiwill-0.1.36.zip`，配置结构版本仍为 0.1.35，升级保留现有设置与持久数据。

使用桥接时，在插件配置中开启 `general.memory_bridge_enabled`，并确认 `general.memory_webui_url` 指向 MaiBot 本机 WebUI。插件从 `MAIBOT_INSTANCE_DIR` 明确指向的实例读取 `data/webui.json`；未设置该环境变量时，桥接会失败关闭。若 WebUI 端口不是 8001，请修改地址。该 Token 有 WebUI 管理员权限，默认不启用；仅建议用于个人单机部署。手动同步只对 `resolved` 候选开放，点击“写入共享记忆”前可在页面查看完整正文。写入后 MaiWill 保留同步状态与记忆 ID；若要删除共享副本，请使用 MaiBot 记忆管理。

本目录就是 MaiWill 项目根目录，也包含可加载的 MaiBot 插件源码。插件在清单中声明只读的 config.get 能力，以公开配置读取接口取用人设并响应 bot 配置热更新，不改变数据库结构或现有用户配置。体力默认值仅作用于新配置；已有配置不会自动覆盖，既有体力账本也不会因上限提高而补满。

插件启用后会自动启动或恢复同一逻辑会话；只有仪表盘明确停止后，人工停止标记才会跨重载保留，点击“启动”可再次运行。进程重启时，未结算的模型调用会保留为“用量未知”记录，余额不伪装扣除零用量，并在决策上下文中说明实际余额可能更低。

插件源码在根目录的 `plugin.py`、`_manifest.json`、`webui.json` 与 `maiwill/` 下。ZIP 的入口以包内相对导入加载，兼容宿主按插件 ID 生成隔离模块名的加载方式。运行 `python scripts/build_zip.py` 会在 `dist/` 生成对应版本的 ZIP；在 MaiBot 插件管理中导入 ZIP 后，安装完成需重启 MaiBot。修改插件源码后重新运行构建脚本即可更新安装包。

## 模型选择

在 MaiWill 插件配置的“意志会话”中设置：

- **沿用模型任务**：下拉选择 `planner`（规划）、`replyer`（回复）、`utils`（通用）、`memory`（记忆）、`mid_memory`（回想）、`learner`（学习）、`fast_model`（快速）、`emoji`（表情）或 `vlm`（视觉）。选项对应原版 MaiBot 1.3.14 的生成任务，不包含向量、语音识别或联网服务任务。
- **指定模型名称（可选）**：留空时沿用所选任务的模型列表和选择策略；填写时只为 MaiWill 请求指定该模型，其余任务参数仍沿用所选任务。填写宿主模型管理中的“模型名称”，不是供应商的模型标识符。

供应商和密钥继续在 MaiBot 原有模型管理中配置。所选任务需配置可用模型，宿主已有的继用规则照常生效；无可用模型或指定名称无效时明确报错，不悄悄改用其他任务。旧版插件配置缺少这两个字段时，默认使用 `planner`，保留原有体力、手机和会话设置。0.1.14 起不再调用需要私有补丁的 `maiwill` 模型任务。

## 长上下文管理

“意志会话”设置中的上下文管理上限默认是 258,000 token，压缩阈值默认是 80%。MaiWill 会在发出请求前估算完整 prompt，约 206,400 token 时先裁剪较早的完整历史单元，目标留下约 129,000 token 的近期历史；模型返回后再用实际 prompt usage 校验并按需整理，降低估算偏差。压缩不会调用另一个模型写摘要，assistant 能力调用和它的结果会成对保留；尚未配对的能力调用记录也会保留。该上限用于管理 MaiWill 自己持久化的长会话，不设置模型供应商硬上限；如果所选模型实际上下文更小，应相应调低插件上限。

共享记忆的正式插件写入 API 尚未公开；个人版可选桥接通过 MaiBot WebUI 的管理导入接口写入，技术上等同管理员操作。它不修改宿主源码，也不提供精细化的插件权限隔离。启用后候选列表显示真实同步状态；普通聊天是否召回这些全局记录由 MaiBot/A_Memorix 自身规则决定。聊天兴趣目前只可靠保存到 MaiWill 本地 outbox，不会自动进入共享记忆。

## 名称

项目名暂定为 **MaiWill**，中文名为 **麦意**。含义是“麦麦自己的意志”，而不是某一个具体生活模块；后续增加能力时不需要重新命名项目。
