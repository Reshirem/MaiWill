# 实施路线

## 当前开发起点（2026-10-25）

用户已确认 0.1.30 安装验证没有明显问题，本次完整隔离测试为 113 项、111 项通过、2 项跳过。当前源码、安装包与已安装运行文件已核对。以下阶段保留实现演进记录；最新建议和验收范围见 [0.1.30 接手评估](development-review-2026-10-25.md)。

建议下一版优先完成日记与学习候选的按需读取、分页查询和独立成果浏览页，让已保存资料在新会话或上下文裁剪后可重新使用；之后依次考虑中文手机输入、运行统计与容量管理。共享记忆写入和跨聊天自我来源召回继续等待正式公开接口。

## 阶段 0：设计基线

状态：设计基线已完成。插件源码已位于本项目根目录，打包脚本会输出 `dist/maiwill-<版本>.zip`。

- 确定项目名和职责边界。
- 固化意志长会话、能力模型、学习记忆契约。
- 记录 MaiBot 当前接口和主程序缺口。
- 不迁移旧麦生活的调度器或状态机；MaiWill 功能优先在插件内实现。
- MaiWill 必须能安装到原版 MaiBot；不修改宿主源码、不依赖私有补丁，不运行时修补或导入内部服务。

完成标准：文档能够回答“谁决定做什么、谁执行、结果写到哪里、聊天如何保持原样”。

## 阶段 1：新插件骨架

状态：插件骨架和核心生命周期已实现。已有 Manifest、配置、SQLite 会话/事件/动作/体力存储、状态与补满 API、兴趣 outbox、WebUI、ZIP 和 AgentLoop。0.1.14 起模型选择使用插件下拉框沿用宿主任务，可选指定具体模型，不依赖宿主补丁；0.1.15 增加可配置的长上下文软上限与阈值裁剪。共享写入仍缺公开接口，真实环境试跑待安排。

- 创建 MaiBot 插件清单和最小配置。
- 实现 `on_load`、`on_unload`、配置更新和一个意志任务。
- 建立事件队列、持久状态、动作日志和可恢复任务。
- 建立代码负责的自主 token 体力账本、恢复速度、储量上限和持久状态；余额可透支。
- 按宿主实际 usage 事后结算 MaiWill 自主模型调用；MaiBot 普通聊天不计入体力。
- 先实现会话生命周期、`rest`、状态查询和体力服务，验证断连恢复及休息计时。

完成标准：重载、卸载、重新加载不会产生重复意志任务；自主模型调用可去重结算，体力按配置速率恢复且不超过储量上限，余额可低于零。

插件启用后自动恢复并运行同一逻辑会话；只有用户明确请求停止才保持停止。重载时恢复活动会话，不要求先有聊天或兴趣事件。

自主长会话持续探索，由麦麦选择休息时长；插件启用后恢复同一个逻辑会话，只有人工停止请求才保持停止。休息时新消息提前唤醒；断连保存上下文并按指数退避恢复，单次休息上限 12 小时。仪表盘提供启动、请求停止、强制停止，并显示状态、休息倒计时和下次重试时间。

## 阶段 2：意志决策

状态：插件侧核心已实现，真实宿主模型调用和 usage 结算已有运行记录；0.1.20 的自主生命周期和会话人工干预通过隔离单测，尚未在当前在线实例安装验证。手机、日记等能力仍待端到端验收。聊天侧 `interest.record` 已可靠写入插件 outbox；意志循环可调用只读 `memory.search`、本地 `diary.write`、学习候选反思和受配置地址限制的 `phone.use`，能力结果返回同一逻辑会话。共享记忆检索仅在存在显式兴趣来源时开放，并由插件固定该来源流 ID 供宿主权限过滤；跨聊天的 bot-self 召回仍待宿主接入。

- 将 `interest.record` outbox 事件交给同一个意志会话；不接收或扫描聊天 Hook。
- 已接入 `memory.search`，映射到宿主 `knowledge.search`，强制启用记忆权限过滤；仅允许引用当前逻辑上下文中显式记录兴趣的来源流，结果作为只读观察返回同一逻辑会话。
- 使用结构化决策 schema，拒绝未知能力和非法参数。
- 为每次能力决策生成稳定步骤 ID；完成结果可安全复用，未知副作用不自动重放。
- 实现同一意志会话的上下文续接、意外中断后的断连恢复，以及 `rest` 到期唤醒和 LLM 失败退避。

完成标准：麦麦可以在聊天中显式记录兴趣；事件进入同一意志会话，由麦麦选择处理或调用休息。没有工具调用时，普通聊天行为与未安装插件时一致。

## 阶段 3：第一批能力

按风险和依赖逐步接入：

1. `diary.write`：已在 MaiWill 数据目录落地可去重的本地 Markdown 日记，并有目录越界保护；后续可再迁移旧麦生活中真正有价值的提示，不迁移旧调度器。
2. `phone.use`：已有插件内 ADB 状态/界面/操作适配，固定配置 IP:端口；未配置 ADB 路径时不暴露给决策模型。MaiWill 会把最近截图作为公开 `llm.generate` 结构化图文 prompt 中的临时图片片段，Base64 不写入持久会话历史。
3. `chat.proactive`：已适配 MaiBot 主动任务接口；仅对记录过兴趣的聊天流提供，并须由意志会话自主判断是否开口。
4. `reflection.create`：已将活动结果整理为本地待同步学习候选，并提供 `reflection.update` 管理处理状态。

## 下一步

候选创建、更新、摘要查看、删除和本地队列已实现，带稳定 ID，删除需用户确认。用户已确认 0.1.30 安装验证没有明显问题。建议下一步补齐日记列表与正文读取、候选按 ID 读取及分页查询，并提供独立的日记与成果页；当前候选列表的条数和正文预览限制，不足以支撑长时间积累后的按需回看。正式 MaiBot 插件接口目前没有共享记忆写入能力；候选保持本地未同步状态，只有正式宿主或公开插件 API 提供写入能力后才接入。上下文管理已有 258,000 token 默认软上限、80% 默认阈值和近期完整历史保留；新增回看能力用于裁剪后的资料取回，不改变同一意志会话的运行方式。

完成标准：意志会话可以自己选择写日记、使用手机或回到聊天，并且每项能力执行结束都会回到同一个逻辑会话。插件侧 `chat.proactive` 已实现，真实普通聊天调度效果仍待端到端验证。

## 阶段 4：共享记忆写入接入

- MaiBot 目前只公开 knowledge.search，旧 ingest_text 插件入口未加载。等待正式宿主或公开插件 API 支持受控写入，当前不修改内部 host_service。
- 核实未来公开能力是否支持 bot_self 来源跨聊天召回；若不支持则保留为明确的功能缺口。
- 给 MaiWill 实现稳定 `external_id`、重试和幂等结果处理。
- 增加从聊天兴趣工具到记忆写入、后台探索再到普通聊天召回的端到端测试。

完成标准：麦麦在一次自主学习后，后续普通聊天可以通过 MaiBot 原有长期记忆召回使用整理结果；不需要 MaiWill 直接改写每次回复提示词。

## 验收场景

至少验证这些场景：

1. 正常聊天中麦麦主动登记一个好奇主题；事件进入同一个意志会话，由其选择研究、整理并写入共享记忆，之后聊天能召回。
2. 麦麦空闲时选择写日记；日记完整保存，适合共享的摘要进入长期记忆。
3. 麦麦选择浏览手机；它可以在同一意志会话中连续操作，直到请求休息或遇到设备/插件故障，中间结果持续回到同一会话。
4. 麦麦调用休息并正常结束会话；仪表盘显示倒计时，到时恢复同一会话。
5. 未请求休息时遇到连接或进程中断；运行时视为断连，保存进度并按退避唤起同一会话继续。模型正常结束但没有请求休息时进入自主等待，不停止长会话。
6. 插件卸载或手机断线；任务可取消或暂停，重载后不会重复写入或重复发送。
7. MaiWill 未启用时；MaiBot 原有聊天和长期记忆行为保持不变。
8. 体力余额透支时，意志模型下一轮能看到负值并自行决定是否休息；普通 MaiBot 聊天始终不受影响。
