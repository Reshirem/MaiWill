## 最值得先做：让探索成果可以回看和复用

当前几处实现限制直接影响长时间运行后的连续性：

1. `plugin.py` 的能力目录提供 `diary.write`，没有日记列表、读取能力；文件虽已保存，模型不能在旧内容离开上下文后按需取回正文。
2. `reflection.list` 只返回最多 20 条候选，每条正文预览最多 1000 字符；存储查询只有状态和数量限制，没有游标、关键词查询或按 ID 读完整正文的工具。
3. 每轮自动注入的是 pending/researching 候选摘要。resolved 候选仍保存在数据库，也可按状态列出，但旧条目和长正文的可访问性不足。
4. `maiwill/context.py` 的裁剪仅保留近期完整历史单元和裁剪标记，不生成语义摘要。显示会话记录独立保留，不能因此推断模型能读取全部旧记录。
5. `webui.json` 只有概览和意识会话页；日记、候选正文没有独立的浏览页面。

### 建议 0.1.31 范围

- 提供 `diary.list` / `diary.read`：按日期、关键词和游标列出已有日记，以插件生成的稳定标识读取正文；读取限制在插件日记目录内。
- 扩展候选查询，增加按稳定 ID 读取正文以及翻页/关键词过滤；正文较长时使用有界分段读取，明确返回截断与后续游标。
- 在同一个意志会话中按需调用这些能力；新建会话或上下文裁剪后，仍可读取过去的成果。列表先给摘要，选中条目后再取正文。
- 新增独立的“日记与成果”页，展示日期、主题、来源、处理状态和正文，支持筛选与导出。沿用现有精简概览的设计。
- 明确区分本地学习候选的处理状态与共享记忆同步状态；现阶段成果仍属于插件本地资料。

验收标准：

- 模拟会话写入日记与长候选，随后裁剪上下文或新建会话，仍能按 ID 读回完整内容并继续同一主题。
- 超过 20 条记录时可完整翻页，无重复遗漏；resolved 条目也可主动找到。
- 升级能够发现现有日记文件和候选，保留原有标识、正文与状态。
- 无效 ID、越界路径、符号链接及过大读取均有明确结果，页面按文本安全显示资料。
- 工具读取结果进入原有串行意志会话；实际新增模型调用继续使用既有 usage 结算。

这部分只为 MaiWill 访问自己已有的生活记录和候选增加入口；普通聊天的长期记忆仍由 MaiBot/A_Memorix 负责。

## 后续优先级

| 顺序 | 工作 | 当前依据与交付价值 |
| --- | --- | --- |
| 1 | 日记与成果回看 | 解决已经保存的材料在上下文裁剪后难以重新使用的问题；建议作为 0.1.31 的完整小版本。 |
| 2 | 手机中文输入与操作反馈 | `phone.use(type)` 明确只接受单行 ASCII；可增加可选的设备输入适配、能力检测和输入结果确认，支持中文主题检索。设备侧组件的选择与安装安排需在实施前明确。 |
| 3 | 运行统计与容量管理 | 现有账本已保存 usage 和动作，但页面缺少按日/会话的消耗、失败和成果统计；截图持续落盘且尚无保留策略。先展示真实指标，再据运行数据优化重复观察、上下文成本和截图容量。 |
| 4 | 共享记忆完整闭环 | 学习成果写入 A_Memorix 并由普通聊天召回价值很高，但当前公开写入/自我来源召回契约仍有缺口，需要正式支持后接入。 |

运行统计应明确区分实际 token、估算上下文大小和未知 usage；目前没有按模型定价的完整成本账本，不将 token 数直接标成货币费用。涉及截图清理时先定义保留期、在途引用与导出需求，保留正在等待视觉输入的文件。

## 共享记忆接口核查

本次同时检查了本机安装环境的宿主能力注册表与 [MaiBot 官方插件 API 参考](https://docs.mai-mai.org/plugin/api-reference)。已核查的注册表只公开 `knowledge.search`，官方 knowledge 章节也只列出搜索，未发现可用的通用共享记忆写入接口。既有接入边界见 [maibot-integration.md](maibot-integration.md)。

将来接入时需要核实：稳定 external_id 的幂等写入、同 ID 异内容冲突、成功凭据、独立同步状态、来源范围以及普通聊天实际召回。`resolved` 继续表示本地整理完成。
