# 设计决策

## D-001：项目独立命名为 MaiWill（麦意）

旧名称“麦生活”强调生活模块；新项目的核心是麦麦自己的意志和能力编排。名称暂定为 MaiWill，后续可在实现稳定后再决定仓库正式名称。

## D-002：MaiBot 聊天流程保持主导

MaiWill 不扫描或总结普通聊天流。正常聊天模型可以在确实产生好奇时调用兴趣记录工具，将事件投递到同一个意志会话；MaiWill 仍不复制 Planner、Replyer 或消息收发流程。这样可以继续使用 MaiBot 已有的人格、表达、工具和聊天记忆行为。

## D-003：只有一个逻辑意志会话

手机、日记、学习、反思和主动聊天都由同一个长期会话选择。能力本身不创建并行决策会话；运行时可以执行持久化、事件排队和恢复，但不替麦麦选择行动。

## D-004：能力与意志分离

能力定义输入、执行和结果；意志会话决定调用和休息。意志会话是启用后的自主长会话，不等待用户派发任务；正常的 `rest` 由模型安排休息，无停止请求时的 `finish` 转成自主等待。只有人工明确停止才保持停止，意外断连则由恢复机制继续同一会话。以后增加新能力时，不需要把它写进每一个旧模块的流程分支。

## D-005：长期记忆以 MaiBot 为权威

MaiWill 可以保留队列和执行状态，但不维护第二套需要聊天同时查询的知识库。学习结果应通过宿主能力进入 A_Memorix，普通聊天仍使用 MaiBot 原有召回。

## D-006：自我来源与聊天来源分开

麦麦自己的知识、经历和表达观察可以跨聊天作为内部背景；具体用户事实和聊天内容仍保留人物或聊天范围。来源元数据必须可追溯，不能全部标成普通聊天摘要。

## D-007：手机只按配置的 IP:端口连接

设备默认地址为 `127.0.0.1:16384`。不依赖序列号，也不增加应用白名单；设备能力的范围由配置地址决定。

## D-008：休息、正常结束和断连分别处理

麦麦通过 `rest` 请求休息；整轮意志 Agent 随后正常结束时，运行时才按所给时长开始计时。无停止请求时错误地选择 `finish` 会变为自主恢复等待，到期后继续同一逻辑会话；只有仪表盘明确停止才进入持久停止。调用或连接异常按断连恢复。休息或断连期间的新事件持久排队；新消息会提前唤醒休息中的同一会话，不建立第二个决策会话。

## D-009：旧麦生活只作为能力来源

迁移时只挑选手机 ADB、日记存储等可复用实现。旧麦生活的状态机、日程、休息、多个后台循环和内部提示词链不作为新项目的默认骨架。

## D-010：以原版宿主的可分发插件为边界

用户于 2026-10-24 明确要求 MaiWill 能作为插件分发，不能要求使用者修改 MaiBot 源码。插件只使用正式公开的 SDK/能力接口，意志调度、模型选择适配和手机实现均留在插件内；不修改或运行时修补宿主，也不导入其内部服务绕过插件边界。已有本地 `maiwill` 模型任务补丁不再是依赖。接口不足时保留本地数据，说明具体缺口和可选方案，与用户讨论后再决定下一步，不自行扩大到宿主开发。

## D-011：MaiWill 自主 token 用量按体力一比一记账

MaiWill 自主调用每消耗一个可观测实际 token，就扣除一个体力单位。MaiBot 普通聊天不计入体力。由代码保存用量、余额、恢复和结算；LLM 只选择行动，不估算或修改体力。余额可降为负数；体力是实际成本信号，不是调用前限额。意志模型看到已结算余额及未知用量提示后，可自行决定何时请求休息。普通聊天继续。

## D-012：体力上限和恢复速度由配置控制

配置中的体力上限决定最多可储存多少体力，恢复速度决定每单位时间恢复多少体力。体力持续恢复，不按每日周期清零。它只调节 MaiWill 自主工作的 token 成本，不改变 MaiBot 普通聊天。

## D-013：自主能力由同一逻辑意志会话调用

日记、手机、记忆、学习和主动交互都是同一意志长会话中的工具调用。单次 LLM API 响应结束是轮次结束，不等于逻辑会话结束；能力结果回到同一会话上下文。会话空闲时事件立即唤醒；运行期间的新事件排队并在安全边界并入。聊天侧的兴趣记录只是事件来源，不把普通聊天流并入意志会话。

## D-014：意外结束视为断连并恢复

如果外层意志 Agent 因连接、服务或进程问题意外中断，运行时视为断连，保存进度并按指数退避尝试唤起同一逻辑会话继续。无停止请求时 `finish` 会转成自主等待，默认 1 小时后自动继续探索。建议初始退避间隔 5 秒、倍增系数 2，最大间隔默认 10 分钟；参数可配置，尝试次数和下次唤起时间持久化。一次 API 响应结束只表示轮次结束；有工具调用时应执行并把结果交回原上下文。

## D-015：休息须请求并正常结束，最多 12 小时

LLM 调用休息能力提交时长；只有外层 Agent 随后正常停止，运行时才开始休息定时。断连或进程退出不会提交休息。模型自行选择的休息最长 12 小时，截止时间持久化；到期或新消息提前到达时恢复同一逻辑会话。仪表盘显示状态和倒计时。

## D-016：第一阶段体力默认值与恢复

体力储量上限默认为 1,000,000 token 等值体力，首次创建账本时初始余额为满额；恢复速度默认为每小时 100,000。插件卸载、MaiBot 关机期间仍按实际经过时间恢复。余额低于上限时连续恢复，负余额也按相同速度恢复，达到上限后停止。修改配置时已有余额按旧恢复速度结算至修改时刻，再应用新上限和速度；配置更新不隐式补满。仪表盘提供经确认的补满按钮。

## D-017：插件下拉选择沿用宿主模型任务

MaiWill 0.1.14 起使用插件配置 `general.model_task` 下拉选择原版宿主已有的生成任务，默认 `planner`，也可选回复、通用、记忆、回想、学习、快速、表情或视觉任务。调用现有 `llm.generate` 时直接传入所选 `task_name`，不注册专用宿主任务。`general.model_name` 留空时沿用任务模型列表和选择策略；填写时仅为该次插件请求指定宿主已配置的模型，其余任务参数仍沿用所选任务。供应商和密钥由 MaiBot 管理。无效模型或没有可用模型时报告宿主错误，插件不静默切换到其他任务。旧配置缺少字段时沿用 Planner。

## D-018：意志循环由 MaiWill 插件运行

MaiWill 在插件 `on_load` 生命周期中启动唯一的异步意志监督/决策任务，并在 `on_unload` 中停止。会话上下文、事件、能力步骤、休息截止时间和断连退避均由插件持久化与恢复。MaiBot 提供模型、记忆等受控能力，不注册 MaiWill 专用调度器，也不接管意志循环。模型调用在调用前记录待确认标记，收到宿主 usage 后按实际 token 事后扣减；体力余额不足不会阻断调用。

## D-019：休息期间事件排队

休息期间，聊天侧显式 `interest.record` 和意识会话用户消息仍可靠写入并作为事件排队，同时提前唤醒同一意志会话。没有新事件时，`rest_until` 到期也会自动唤醒。

## D-020：断连稳定窗口

连续断连次数在意志会话稳定运行达到配置的稳定窗口后清零，不能由单次模型请求成功清零。当前默认稳定窗口为 60 秒。

## D-021：决策循环可注入测试

MaiWill 的 AgentLoop 使用可注入决策器和能力处理器，使单一会话、事件确认、能力往返、休息及退避可用假模型验证。自主调用按模型返回的实际 usage 事后记账，不使用体力预算闸门。

## D-022：体力允许透支并由模型决定休息

体力是已发生自主模型成本的余额与恢复指标，不是开始下一次模型请求的许可额度，也不设单次体力预算。每次决策结束后按 MaiBot 返回的实际 usage 扣减，余额可以为负。最新余额和 usage 未知提示进入下一次模型决策上下文；模型在看到负余额或低余额后自行选择是否休息。最大储量和按经过时间恢复的既定设置保持不变。

## D-023：共享记忆搜索必须带显式聊天来源范围

MaiBot `knowledge.search` 以 `chat_id` 解析聊天检索范围；MaiWill 的自主调用不应在空范围下查询共享记忆。插件仅在当前逻辑会话上下文含 `interest.record` 事件时开放 `memory.search`，要求模型引用该兴趣的稳定 ID，并由插件从受信 outbox/context 中解析并固定来源流 ID。跨聊天的 `bot_self` 记忆召回应由宿主/A_Memorix 正常召回策略实现，不得通过 MaiWill 空范围搜索绕过聊天权限过滤。

## D-024：按实测阈值确定性裁剪长会话历史

MaiWill 默认以 258,000 token 为软上下文管理目标，在请求前估算的完整 prompt 或上一轮宿主 usage 的 prompt token 达到 80%（约 206,400）时，裁剪最早的完整历史单元，目标保留约 129,000 token 的近期历史。请求前预估用于给突增内容留余量，宿主 usage 用于校验实际用量并弥补估算偏差。上下文上限和阈值都可配置；此目标不覆盖模型或供应商的硬限制，也不向请求传递额外输出上限。当前不调用第二个模型生成摘要；assistant 能力调用与对应结果作为一组保留，未完成或孤立能力记录固定保留。历史 token 估算用于触发预检与选择裁剪边界。
