## 用户已确定的产品边界

- MaiBot 普通聊天流程保持原样。MaiWill 不替代 Planner、Replyer 或聊天人格。
- 不扫描聊天流，也不做独立聊天观察。聊天模型确实产生好奇时才显式记录兴趣。
- 手机、日记、学习、记忆整理和主动交互由同一个逻辑长会话决定；一次模型 API 响应结束只是一个轮次，能力结果尽快回到同一会话，LLM 可继续选择行动或调用休息。
- 麦麦持续自主探索；没有可靠行动时自行选择休息时长，休息到期继续同一会话。体力透支或低于上限 10% 时优先休息。只有明确人工停止才保持停止；无停止请求的意外结束转为自主恢复等待。连接或进程异常采用持久化指数退避。
- 意志决策不可并行。会话空闲时事件立即唤醒；活动期间到达的事件持久化排队并在安全边界进入同一会话。
- 插件启用后自动启动同一逻辑会话；仪表盘提供请求停止和强制停止，人工停止跨重载保持。
- 逻辑会话不等于服务端原生会话；评估无状态 API 重放历史带来的延迟和重复 prompt token 成本，并将上下文整理纳入同一会话设计。
- 只有 MaiWill 自主模型调用按实际 token 一比一扣体力；MaiBot 普通聊天不扣这份体力。体力是事后成本信号而非调用限额，允许透支；模型看到负余额后自行决定休息。
- 意志模型在插件中通过 general.model_task 下拉选择宿主已有生成任务，默认 planner；general.model_name 可选指定已配置的模型。模型列表、供应商与密钥继续由宿主管理。
- 意志循环由 MaiWill 插件在加载时启动、卸载时停止，并由插件持久化状态和恢复；MaiBot 不注册 MaiWill 专用调度器。
- “回复速度”在此指体力恢复速度。体力上限和恢复由代码计算。
- 手机只连接配置的 IP:端口，默认 `127.0.0.1:16384`；不用序列号、不设应用白名单。设备地址是连接范围，麦麦决定设备内如何使用。
- 学习结果进入 MaiBot A_Memorix，由原有记忆召回供聊天使用。
- 不照搬旧麦生活的多套调度器、状态机和知识链；只迁移有价值的能力。
- 开发流程应避免每次改动都卸载 ZIP 重装，并保持配置和数据不随代码更新丢失。

## 已确认的设置语义

- 体力上限是体力池最大储量，不是每日消费上限。新账本首次初始化为满额；默认储量上限为 1,000,000 token 等值体力，默认每小时恢复 100,000。
- 插件卸载和 MaiBot 关机期间继续按实际经过时间恢复体力；恢复不会因每日边界清零。
- 仪表盘提供显式确认后将体力余额恢复至上限的按钮。
- 断连退避在逻辑会话稳定运行 60 秒后清零，不以单次 API 成功作为清零条件；稳定窗口保留为可配置项。
- 休息暂停自主活动；用户消息和兴趣事件持久排队，休息期间新事件可提前唤醒同一会话，rest_until 到期也会唤醒。
- 休息由模型决定，仅整轮 Agent 正常结束后开始计时，最长 12 小时。意外结束进入自主恢复等待，连接错误或进程退出按退避恢复。

1. 在专属测试设备上验证 `phone.use` 的 ADB 连接、控件读取、点击、输入与截图视觉理解。试跑前需在插件配置填写专属模拟器 ADB 完整路径。
2. 在原版 MaiBot 验证模型任务选择、可选模型名称、配置热更新、真实 usage 与 80% 上下文整理、负余额/未知 usage、记忆检索权限、本地日记、主动表达和休息恢复。
3. 插件侧 `chat.proactive` 已通过 `maisaka.proactive.trigger` 接入；事件中仅记录过兴趣的聊天流可作为目标，仍待真实聊天调度试跑。
4. 已核实 `knowledge.search` 需要明确 `chat_id` 才建立聊天范围；MaiWill 现仅在显式兴趣记录上下文中开放搜索，并固定使用对应 `source_stream_id`。
5. 个人桥接是临时方案，显式写入后候选会保存同步状态和 MaiBot 记忆 ID；普通聊天 bot-self 召回、兴趣 outbox 自动同步仍等正式公开 API。

## 第一阶段验收

- 加载、卸载、热更新和重载没有重复后台任务；卸载会等待任务收尾。插件启用后自动启动或恢复会话，人工停止标记跨重载保留。
- 仪表盘请求停止会让模型自行收尾，强制停止会立即中断当前任务；无停止请求时 `finish` 进入自主等待并继续探索。已过期休息只唤醒一次。
- 活动会话的显式事件唤醒唯一意志 Agent；用户消息或兴趣事件会提前唤醒休息会话。异常中断时恢复同一逻辑会话。
- 仅 MaiWill 实际 usage 扣体力；1 token 扣 1 体力；恢复按配置连续计算且不超过上限。
- 同一 usage 重放不重复结算；重启可恢复待结算状态，且体力余额可为负。
- usage 缺失或账本写入失败不会被当作零消耗，并有明确可恢复状态。
- 进程重启时，未结算的模型请求标记为 usage `unknown`；下一轮决策知晓余额仅代表已知成本。
- 体力不足或为负不会阻止新自主模型调用；普通聊天在插件关闭或卸载时保持原样。
- 模型选择休息时自主休息；意外结束进入自主恢复等待。只有明确人工停止才进入停止状态。
- 仪表盘能显示活跃、休息、断连/重连、当前退避间隔及下次唤起时间、负体力余额和停用状态。
- 工具结果返回后可立即继续原会话；空闲时的新事件立即唤醒，运行中的新事件不并行启动第二个自主 LLM 请求。
- 连续调用失败采用指数退避，默认最大间隔 10 分钟并可配置；重启不重置退避，不将代码退避显示为模型选择的休息。

## 后续能力的边界

- `interest.record` 只接收聊天模型显式提交的主题；先可靠写入，再唤醒意志，不读取聊天记录。
- 手机先验证默认地址 ADB 连接、截图和输入；所有命令目标固定到配置设备。
- 记忆写入先确认幂等 ID、来源元数据和 `bot_self` 召回，再做端到端验证。
- 日记、主动发言等只作为能力加入，不建立第二套自主调度器。
