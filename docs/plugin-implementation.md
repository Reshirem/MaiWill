# MaiWill（麦意）

MaiWill 是 MaiBot 插件，由长期逻辑意志会话统筹自主能力。当前版本 0.1.30，使用原版 MaiBot 公开接口，安装不要求修改宿主源码或应用私有补丁。事件、动作、探索目标、会话状态与 token 体力账本都保存在插件专属数据目录。

## 当前实现

- 使用独立 SQLite 数据库持久化单一逻辑会话、幂等事件、动作状态与自主 token 资源账本。
- 默认体力储量为 10,000,000 token 等值体力，恢复速度为每小时 1,000,000；新账本从满额开始，既有配置不会被安装包默认值覆盖，既有账本按经过时间结算且不会因提高上限而补满。
- 保存休息请求，只有外层会话正常结束后才开始休息；进程重载会把未确认休息/活动转为指数退避恢复，普通配置热更新不误计为崩溃。
- 插件启用后默认自主运行；麦麦主动检查能力和持久上下文，无事可做时自行选择休息时长。体力透支或不高于上限 10% 时优先恢复。仪表盘停止操作仍可保持人工停止状态，该状态跨插件重载保留。
- 模型调用前持久化用量待确认标记，调用后按实际 usage 结算并按 request ID 去重；体力可低于零。
- 进程重启时将未结算模型调用标记为用量未知，向仪表盘与后续决策显示未知状态；未知用量不会被算成零，也不作为调用前限额。
- 提供聊天侧 `interest.record` 工具，显式兴趣会进入持久 outbox；当前状态为等待宿主共享记忆写入能力接入，不会伪报已同步。
- `reflection.create` 将活动反思保存到本地 `learning_candidates` 表，按来源和内容计算稳定 `external_id`，重复调用幂等；`reflection.update` 管理候选处理状态，`reflection.list` 按状态查看候选。仅用户二次确认的仪表盘操作可以 `reflection.delete` 纯本地候选；这些操作均不执行共享记忆同步。
- 意志会话仅在当前逻辑上下文有显式兴趣事件时可调用只读 `memory.search`，必须引用兴趣 ID；插件从已存兴趣上下文取得来源聊天流，并固定 `chat_id` 调用 MaiBot `knowledge.search`，保留宿主权限过滤。没有兴趣来源时不允许共享记忆检索。
- 意志会话可调用 `diary.write` 将标题与正文保存为 MaiWill 数据目录内的 Markdown 日记；路径按本地日期与内容摘要生成，相同输入重试不会重复生成文件。
- 意志会话可调用 `phone.use`，通过配置的 ADB 完整路径连接唯一 IP:端口；支持状态、控件树、点击、滑动、输入、启动 App、设备 shell/ADB 子命令和截图落盘，不支持模型自行选设备。
- 意志会话可用 `chat.proactive` 将表达意图交给 MaiBot 正常聊天流程；目标限于当前上下文中的显式兴趣事件聊天流，并使用 AgentLoop 的持久动作步骤防止未知结果自动重放。
- 手机配置默认为 `127.0.0.1:16384`，ADB 程序路径默认为空；需在插件设置中手工填写专属模拟器的 `adb.exe` 路径后才会尝试连接。
- 决策请求可携带最近一次 `phone.use` 截图作为临时图文消息；Base64 只存在于本次请求，不写入 SQLite 上下文。插件验证截图路径、PNG 签名和 IHDR 分辨率，并限制读取大小与尺寸；只选择 `vlm` 任务不会自动拍摄图片。
- 意志会话在插件设置中通过 general.model_task 下拉选择宿主已有生成任务，默认 planner；可选的 general.model_name 只为本插件请求指定具体模型。不依赖专用 maiwill 宿主任务。
- 意志监督器由插件自己持有，加载时恢复同一会话并自动持续探索；空闲结束会转为自主休息。休息期间的新用户消息或兴趣事件会提前唤醒会话。卸载时停止监督器；MaiBot 提供受控 LLM 能力，不注册插件专用宿主调度器。
- 插件内 AgentLoop 已实现注入式决策、无固定步数上限的串行能力往返、上下文恢复、事件确认和 `rest` 提交；动作结果持久化后才确认对应事件，重载时不会自动重放结果未知的外部副作用。
- 意志请求会根据启用能力、当前目标、近期明确兴趣、本地待处理候选和近期成功行动生成最多 8 个有来源的探索入口；无目标时可先做配置手机的只读发现。入口只提供方向，不制造任务，且手机读观察后暂不重复建议相同发现。
- 每轮决策上下文开头通过 MaiBot SDK 公开配置能力引用当前昵称、人格设定、行为风格和表达风格；每字段有长度上限，空配置跳过，并在人格配置热更新后重新读取。表达风格适用于本会话的所有自然语言内容（包括 reason 与 reply），同时必须保持决策 JSON 结构和工具参数有效；行为风格不覆盖 MaiWill 的目标、证据、安全及体力规则。
- 没有用户任务、活动目标或兴趣来源时，不把“没有目标”视为休息理由；模型可从已启用能力、已配置手机可见内容、已有日记和本地学习候选中自行选一个低风险小发现。单步发现无需预先建目标；仅在发现值得持续调查的主题时，以真实成功行动为证据创建目标。手机探索限制在只读或可恢复操作，不发送消息、提交表单、购买、删除、修改设置或读取、暴露私人凭据。
- 提供精简 WebUI 会话概览，显示会话状态、体力、待处理事件、探索目标和生命周期控制；候选、兴趣与详细体力账本不在概览常驻铺开。
- “意识会话”页面按时间展示用户干预、麦麦回复/决策说明、工具结果与事件观察；支持多行输入、处理状态、历史翻页和每 3 秒刷新，并显示当前已保存模型上下文的消息数、字节数和估算 token 数。显示记录独立于模型上下文保存。
- 插件可在 WebUI 热重载，持久数据写入宿主提供的 MaiBot 数据目录。
- 插件入口使用包内相对导入，适配 MaiBot 根据插件 ID 生成的隔离 Python 模块名。
- ZIP 包包含带有 `[plugin].config_version` 的初始 `config.toml`，避免首次安装生成无版本配置。

## 自主长会话、人工干预与新会话
启用插件后，麦麦在同一逻辑会话中持续检查可用能力、近期上下文、待整理候选和已收到的观察；有价值且有依据的行动由麦麦自己选择。没有可靠行动时，由麦麦自主决定休息时长，到期后继续探索。体力透支或不高于体力上限 10% 时，提示模型优先休息恢复。无停止请求时意外结束会转为自主恢复等待。连续三次无效决策后保留未处理消息并按断连退避重试。

输入消息后按 Enter 或点击“发送”，Shift + Enter 换行；中文输入法选字时不会误发送。每条最多 4000 字符，空白内容会被拒绝。发送只投递 `operator.message`，运行中的循环在下一轮决策读取；人工停止时先保存，需点击“启动会话”处理；休息时新消息会提前唤醒，重连时保留到下一次尝试。当前调用刚好选择 `finish` 或 `rest` 时，新到消息继续排队，不会被误标为处理完成。

用户消息、事件写入和去重在一个 SQLite 事务中完成。发送超时后保留输入和提交 ID，在当前页面重试同一内容不会重复入队。重新加载页面会清除尚未发送的草稿与临时提交 ID，应先查看记录再决定是否再次发送。“已处理”表示包含该事件的一轮决策及能力结果已经持久化，不代表模型一定完成了用户要求。

模型可在任意决策 JSON 中附加 `reply`（最多 4000 字符）直接回复页面用户，同时保留 `use_capability`、`rest`、`finish` 的行为。`finish` 只响应人工停止请求；没有停止请求时转为默认一小时的自主恢复等待。页面只展示公开回复、简短决策说明和执行结果；不额外请求模型输出内部推理，不新增自主模型调用，不向普通聊天发送这些页面回复。

显示记录采用独立的 `will_conversation` 表，不随上下文裁剪或新建会话删除；升级时仅迁入旧版仍保留的上下文，已裁剪的历史无法补回，旧记录没有可靠时间则标为“升级前记录”。新建会话会停止当前 Agent、把未确认的外部动作记为结果未知，生成新的逻辑会话 ID 并清空模型上下文；体力账本、学习候选、兴趣 outbox 和待处理事件保留。页面可从“记录会话”下拉框查看旧记录。每页最多 40 条（接口上限 50 条），大结果按字节预算减少条数；单条过大的正文/详情会带截断说明，工具详情可展开。概览和控制接口不返回完整模型上下文。

页面使用公开 WebUI v2 `custom_pages` 和 `window.maibot` 桥接，HTML/CSS/JS 全部随 ZIP 内联打包。安装环境需支持该页面能力，只升级 Python SDK 不会升级宿主 WebUI；具体协议见 [MaiBot 官方 WebUI 文档](https://docs.mai-mai.org/plugin/webui-pages)。0.1.20 新增 `general.idle_wait_seconds` 设置，配置版本为 0.1.20；0.1.21 保持配置结构不变，旧配置和现有体力账本均可继续使用。

## 模型配置

插件配置的“意志会话”提供“沿用模型任务”下拉框，可选 planner（规划）、replyer（回复）、utils（通用）、memory（记忆）、mid_memory（回想）、learner（学习）、fast_model（快速）、emoji（表情）、vlm（视觉），默认 planner。选项是原版 MaiBot 1.3.14 的生成任务，不包含向量、语音识别或联网服务。

“指定模型名称（可选）”留空时沿用所选任务的模型列表和选择策略；填写时仅为 MaiWill 指定宿主模型管理中的该模型，其余任务参数仍沿用所选任务。填写模型名称，不是供应商模型标识符。供应商与密钥仍在 MaiBot 中维护，不改变普通聊天任务。任务未配置或模型名无效时报告错误；宿主已有继用规则照常生效。

旧配置缺少新增字段时默认沿用 Planner，并保留启停、恢复、体力及手机设置。新字段为 [general].model_task 和 [general].model_name。

## 自主模型调用和体力结算

意志循环调用所选宿主模型任务，不额外覆盖输出长度；宿主模型/任务配置和供应商限制仍然生效，调用不受体力余额检查阻断。宿主返回的可信 usage 按 prompt_tokens、completion_tokens、total_tokens 记账，允许余额透支；最新余额和未知 usage 说明进入后续决策上下文。缺失 usage 不伪报零消耗。

休息时没有正在运行的意志模型或手机能力。活动期间意志可以调用日记能力，将记录写入 MaiWill 数据目录；兴趣记录由聊天工具写入 outbox，如果会话在休息中，会立即唤醒原会话处理。MaiBot 当前未提供插件侧 A_Memorix 写入能力，所以兴趣不会立即进入共享记忆。宿主源码复核还发现空 `chat_id` 不会建立 A_Memorix 聊天检索范围；因此 MaiWill 不再向无范围请求开放共享记忆搜索。跨聊天 `bot_self` 召回应由宿主/A_Memorix 正常召回流程实现。

插件只使用公开 SDK/能力接口，不修改宿主文件或导入内部服务。正式宿主尚未公开的共享记忆写入能力保持未接通，数据继续保存在插件本地，不要求使用者修改 A_Memorix。已有单测及原版接口离线验证，真实模型、设备和长期运行仍需试跑。



## 探索目标账本（0.1.22）

SQLite 保存当前和历史目标、逐条进展、来源引用和下一步。一个活动目标由部分唯一索引保证；主题规范化后按七天冷却重复创建。创建目标的来源必须在 interest_outbox、learning_candidates 或最近七天成功动作中；推进/完成引用新的来源或成功行动，失败或未知的动作不作证据。新建逻辑会话只清空模型上下文，不清空此账本。


## 目标停滞与时间线（0.1.23）

活动目标从创建或最近一次有证据的 progress 起算；超过 24 小时会在决策上下文中标记 is_stalled。replan 只能写下一步和客观障碍，不会刷新 last_progress_at，也不能用来伪造进展。概览页显示停滞标记、有效进展时间和最近 30 条目标事件。升级时 SQLite 增加 last_progress_at，并在旧进展表约束中加入 replanned 事件，保留原事件 ID 和内容。
