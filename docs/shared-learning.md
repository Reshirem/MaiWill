# 共享学习与长期记忆

## 学习闭环

MaiWill 的学习不是独立知识库，也不是模型训练。普通聊天模型在确实产生好奇或知识缺口时主动记录兴趣，后台意志再决定是否继续了解；学习结果形成候选，由用户确认后可通过个人 WebUI 桥接写入 MaiBot A_Memorix。

```text
聊天模型主动记录 / 活动结果
  -> MaiWill 本地兴趣 outbox
  -> 意志判断是否值得处理
  -> 查询已有记忆
  -> 观察或行动（手机、知识归类、日记）
  -> LLM 整理事实、经验和表达观察
  -> 用户确认后幂等写入 A_Memorix
  -> 普通聊天按 MaiBot 原有召回流程使用
```

## 学习来源

### 聊天中的兴趣记录

MaiWill 不扫描聊天流，也不在回复之后另起模型来分析聊天。MaiBot 的正常聊天模型可以在提示词引导下主动调用 `interest.record`，记录真正想继续了解的主题或明确的知识缺口。这样记录的是麦麦自己表达的兴趣，而不是插件对聊天的推测。兴趣会保存到本地 outbox 并唤醒意志会话，但不会自动进入 A_Memorix。

兴趣记录作为结构化候选进入 MaiWill 的本地 outbox，并带有稳定 ID 和简短理由。正式插件 API 仍无共享记忆写入能力，因此兴趣候选会留在本地，不会伪报进入 A_Memorix。工具调用后通知同一个逻辑意志会话；是否立刻研究仍由意志决定。如果会话正在休息或断连，事件先排队。没有兴趣记录工具时，单独提示模型“记住这个兴趣”只能影响当前对话，无法可靠保存到后续会话。

候选应带有：

- 可选来源聊天流和消息锚点；优先引用已存在的 MaiBot 记忆，不复制整段聊天。
- 主题文本和候选类型（未知、兴趣、待核实、表达观察）。
- 麦麦自己的简短兴趣理由。
- 是否已经被处理、跳过或合并。

### 麦麦主动感兴趣的主题

意志可以从长期记忆中的兴趣记录、最近活动结果和已有知识中选择主题。它可以使用手机搜索，也可以只在本地记忆中归类；“现在不想查”是合法决策。

### 手机见闻

手机能力返回屏幕可读内容和行动结果，`reflection.create` 决定哪些内容值得保存。默认写入的是整理后的摘要、事实、经验和表达观察，不把每一帧截图或全部 UI 文本当作长期记忆。

麦麦可以选择分享截图；分享是能力副作用，由意志显式决定，不由见闻整理自动触发。

### 日记和反思

日记是麦麦自己的生活记录，可以由意志在空闲时写，也可以在一次学习或聊天后写。日记全文属于本地生活 artifact；只有适合跨聊天参考的内容才生成摘要或经验写入 A_Memorix。

## 记忆分类

第一版建议使用明确的来源类型，而不是把所有内容伪装成聊天摘要：

| `source_type` | 内容 | 默认用途 |
| --- | --- | --- |
| `mai_will.curiosity` | 麦麦主动记录的兴趣、知识缺口或待研究问题 | 作为意志会话的学习候选，也可供聊天理解麦麦近期关注点 |
| `mai_will.knowledge` | 学到的稳定知识或概念解释 | 相关话题的聊天参考 |
| `mai_will.experience` | 麦麦自己的探索、判断和经历总结 | 形成连续的自我经历 |
| `mai_will.expression` | 表达节奏、修辞、互动方式和新例句 | 表达选择参考 |
| `mai_will.phone` | 手机阅读或操作后确认的见闻 | 话题和兴趣参考 |
| `mai_will.diary` | 日记的可共享摘要 | 自我连续性和后续反思 |

具体的 `source_type` 名称可以在实现阶段根据 A_Memorix 的接入约定调整，但来源必须可追溯、可区分、可幂等。

## 统一写入契约

每条同步任务都应提供：

```json
{
  "external_id": "mai-will:phone:sha256:...",
  "source_type": "mai_will.phone",
  "text": "整理后的可检索内容",
  "chat_id": "",
  "timestamp": 0,
  "tags": ["phone", "self_learning"],
  "metadata": {
    "owner_scope": "bot_self",
    "origin": "phone",
    "origin_session_id": "",
    "candidate_id": "",
    "confidence": 0.82,
    "observed_at": 0
  }
}
```

`external_id` 由来源、稳定主题标识和内容版本组成。重复同步返回幂等结果；内容确实更新时产生新版本或显式替代关系，不覆盖无关记忆。

插件本地 `learning_candidates` 表保存完整的候选正文、来源元数据、稳定 `external_id` 和处理状态，供候选同步到宿主前查看和恢复。首版内容仅由 MaiWill 自主反思生成，兴趣 outbox 仍单独保留。状态可以是 `pending`、`researching`、`resolved`、`deferred` 或 `dismissed`；`resolved` 表示整理完成，不表示共享记忆已同步。共享记忆同步状态独立保存为未同步、同步中、已同步或失败，并记录 MaiBot 返回的记忆 ID、同步时间和错误。

`reflection.create` 接受来源类型 `mai_will.knowledge`、`mai_will.experience`、`mai_will.expression`、`mai_will.phone` 或 `mai_will.diary`，以及标题、整理后的内容、标签和可选来源引用。插件根据来源和候选内容生成确定性的 `mai-will:learning:sha256:...` ID；同内容重试会返回现有记录，不重复创建。`reflection.update` 只更新本地工作流状态，`reflection.list` 按状态列出本地记录。用户可以在二次确认后用仪表盘 `reflection.delete` 永久删除纯本地候选；已同步候选保留本地关联，不能从 MaiWill 删除，以免丢失共享副本的映射。候选列表和正文显示本地整理状态与共享记忆同步状态。0.1.32 起，显式启用个人用途的 WebUI 桥接后，用户可在“日记与成果”页确认将已整理候选写入全局 A_Memorix；意志会话也可选择 `memory.write`。两种入口都只提交数据库中已保存的原文，并为失败/中断保留可重试状态。

## 召回规则

普通聊天继续调用 MaiBot 的原生记忆召回。MaiWill 不扫描每个聊天 Hook，也不手工把本地摘要拼进每次回复提示词。聊天模型确实产生好奇时，通过 `interest.record` 明确写入兴趣记忆；后续聊天再由 MaiBot 原有召回流程按相关性使用。

共享记忆需要区分两种范围：

- `bot_self`：麦麦自己的知识、经历和表达观察，可以跨聊天流作为内部上下文召回。
- `person_or_chat`：与特定用户或聊天有关的内容，继续遵守 MaiBot 的人物和聊天范围过滤。

共享记忆只作为内部推理背景，除非聊天流程或麦麦的正常表达决定说出来，否则不逐字引用原始来源。手机属于麦麦专属设备这一事实不改变聊天中私人消息的原有归属；从私人聊天抽取的用户事实仍应保留人物范围。现有 MaiBot `knowledge.search` 通过 `chat_id` 建立检索范围，但没有 `bot_self` 例外，因此 MaiWill 目前只在显式兴趣记录提供来源聊天流时开放共享检索，并强制使用该流 ID；空闲探索不检索共享记忆，避免查询范围为空时被误当成全局查询。真正的跨聊天自我记忆召回必须由 MaiBot/A_Memorix 提供明确的 `owner_scope=bot_self` 策略。

## 过期与删除

MaiWill 的候选、执行记录和重试队列可以设置保留时间；一旦写入 A_Memorix，长期记忆的生命周期由 MaiBot 统一管理。插件不能只删除本地副本就声称记忆已经删除。

删除或修正操作必须使用 `external_id`、来源元数据或 MaiBot 提供的管理接口，确保向量、实体、关系和外部映射一起处理。

## 反馈

第一版只记录“写入成功、召回成功、用户或麦麦明确修正”这些可验证信号，不用隐式地把每次聊天都当成学习。后续可以让意志选择复盘被召回的知识，生成修正或合并任务。
