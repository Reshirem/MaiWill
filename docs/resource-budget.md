# 资源预算与体力

## 体力语义

MaiWill 只记录自主意志会话发起的模型调用；MaiBot 普通聊天不计入这份体力。体力按已发生的模型成本事后扣减，是麦麦决定活动节奏和休息时机的信号，不是调用许可额度。体力不足、余额为零或余额为负都不会阻断新的自主模型请求。

- `1 token = 1 体力`。以 MaiBot 返回的 `total_tokens` 为准，prompt、completion 用于展示与审计。LLM 自报数值无效。
- 每轮重发的会话历史也包含在该次实际 prompt usage 中，照常扣体力。
- 不调用模型的手机点击、等待等操作本身不扣 token。
- 余额允许为负。模型会在决策上下文里看到最新的已结算余额，可据此自行请求休息。仪表盘显示“余额 ÷ 储量上限 × 100%”；透支时比例为负数，并以千位逗号格式显示体力余额、体力上限、每小时恢复量和累计 token。
- 如果请求结果没有可信 usage，系统记录“用量未知”，不会把它伪装成零消耗；决策上下文会说明真实成本可能更高。

## 储量与恢复

| 设置 | 默认值 | 含义 |
| --- | ---: | --- |
| 体力上限 | 1,000,000 | 体力池最大储量，不是消费上限 |
| 每小时恢复 | 100,000 | 按实际经过时间连续恢复；停用或关机期间也计算 |
| 首次初始化 | 满额 | 新账本首次创建时余额等于上限 |

恢复公式为：

```text
恢复后余额 = min(体力上限, 上次余额 + 恢复速度 × 经过小时数)
结算后余额 = 恢复后余额 - 实际 total_tokens
```

公式对负余额同样适用。例如余额为 -200,000 时，每小时恢复 100,000，两个小时后余额为 0。余额到达上限后停止恢复。修改配置时，先按旧速率结算至修改时刻，再应用新上限与速率；配置更新不会隐式补满。仪表盘提供经确认后将余额恢复至上限的按钮。

## 请求记录和结算

每次模型调用发出前，MaiWill 生成本地 `request_id`，持久化一个用量待确认标记；该标记不扣减余额、不限制请求，也不预留 token。调用结束后，若宿主返回完整且有效的 prompt、completion 和 total usage，则在同一幂等事务中写入用量记录、按实际 `total_tokens` 扣除体力并结清标记。相同 request ID 的结果重放不会重复扣费。失败请求若宿主明确返回可信 usage，照常按实际费用扣减。

如果调用抛错、进程在等待时退出、usage 字段缺失或数据不完整，待确认标记转为 `unknown`。它不占用储量、不阻止后续调用，但状态页和下一次决策都会显示未知请求数，且提示余额只反映已知成本。MaiBot 当前没有稳定 provider request ID，因此未知用量无法自动对账；不得将其记为零或猜测扣款。若本地账本在收到 usage 后写入失败，Agent 将进入断连退避，已有标记在重载后仍显示未知，便于人工识别。

每条已结算记录至少包含本地 request ID、时间、模型、prompt/completion/total tokens、成功状态和 usage 来源。累计消费统计按已结算 usage 汇总。

MaiWill 不向模型调用设置单次决策输出 token 上限。模型供应商或模型服务自身可能有其固有限制；MaiWill 插件不额外限制。

## 决策上下文

在调用意志模型前，插件按当前时间先结算离线/运行期间恢复，然后将余额、储量上限、每小时恢复值、累计已知用量、未知请求数及余额说明放进 `resource` 决策上下文。请求完成后插件先结算 usage；AgentLoop 的后续能力往返会在下一次模型调用前刷新上下文，因此模型看到最新余额。模型可选择 `rest`，休息时长仍由代码封顶为 12 小时，并且只在 Agent 正常结束后开始计时。

体力恢复不会自动唤醒休息或断连中的会话，也不会仅因余额低而让会话进入等待状态；是否休息由模型决定。普通 MaiBot 聊天不扣这份体力，也不受体力状态影响。

## 验收标准

- 实际 1,000 token usage 扣除恰好 1,000 体力，重复结算同一请求不重复扣减。
- usage 大于当前余额时，余额成为负数，模型后续能看到负值且仍可发起下一次请求。
- 负余额持续按配置速度恢复，达到储量上限后停止。
- 首次账本满额；卸载或关机期间按经过时间恢复；人工补满将余额设置到上限。
- usage 缺失或调用中断保留未知记录并向模型提示不确定性，不报为零，不阻断后续调用。
- MaiBot 普通聊天不消耗 MaiWill 体力，也不会被体力状态阻断。
