# 意志长会话、断连恢复与休息

## 核心模型

0.1.19 起在插件工作区提供“意识会话”页。0.1.20 起，插件启用后默认持续自主探索。用户输入可靠入队，活动会话在下一次模型请求读取；新消息或兴趣事件会提前唤醒自主休息中的会话。明确人工停止后保持停止，消息留在队列直到重新启动。模型可通过 reply 字段回应页面用户。

页面记录独立保存，按游标向前翻页，每 3 秒刷新当前页。记录用户输入、决策说明/回复、工具结果和事件观察，不展示系统提示或模型私有推理；只有对应事件和一轮结果已持久化后才标为已处理。

MaiWill 维护一个长期的逻辑意志会话，统一检查可用能力、近期上下文、待处理事件和本地学习候选。有价值且有依据的行动由麦麦决定；没有可靠行动时，麦麦选择休息时长，到期后继续同一会话。体力透支或余额不高于上限的 10% 时应优先休息。

一次 API 响应结束只是一个轮次。能力执行结果返回同一会话上下文；只有完整 Agent 运行结束才开始休息或恢复等待。没有停止请求的意外结束转为自主恢复等待；连续三次无效决策会保留未处理消息并进入断连退避。

| 整轮运行结果 | MaiWill 处理 |
| --- | --- |
| 正常请求 rest | 按麦麦选择的时长休息，到期后继续 |
| 意外结束，无人工停止 | 进入自主恢复等待后继续探索 |
| 结束且收到人工停止 | 进入 STOPPED，等待用户重新启动 |
| 连续无效决策或连接/进程异常 | 保留消息，按退避恢复原会话 |

“同一个会话”描述 MaiWill 侧的逻辑身份和可恢复上下文，不保证供应商 API 原生保留上下文。无状态 API 可能需要在每轮重发仍相关的历史，长历史会增加延迟、prompt token 和体力成本。实现应实测各轮请求的实际 token 与响应耗时，并通过同一会话内的上下文保留/整理改善体验；不得把隐藏的第二个 LLM 摘要链当作会话恢复。

上下文管理默认目标上限为 258,000 token，压缩阈值默认为 80%。MaiWill 在发出下一次决策前估算完整 prompt；若达到约 206,400 token，就先确定性地裁剪较早的完整历史单元，目标保留约 129,000 token 的近期记录。模型返回后再用实际 prompt usage 校验并在需要时整理，避免估算偏差累积。此值是可配置的软管理目标，不会覆盖所选模型的真实上下文限制。当前实现不调用另一模型生成摘要；最近的完整能力调用和结果一起保留，未完成的调用记录固定保留。

保持同一上下文是为了让行动连续、反馈快速：模型决定一个动作，代码执行对应工具，结果尽快交回同一会话。不得为日记正文、手机操作计划、知识整理等活动再启动互不共享上下文的自主决策会话。纯确定性代码仍负责设备 I/O、存储、校验、体力和生命周期。

意志循环的运行器由 MaiWill 插件持有：插件加载时创建唯一后台任务，卸载时停止并等待任务收尾；事件队列、上下文、动作步骤、休息和重试时间都由插件持久化。MaiBot 提供模型调用等受控能力，不注册 MaiWill 专用调度器。插件设置通过 `general.model_task` 下拉选择沿用的宿主任务，默认 `planner`；可选的 `general.model_name` 仅覆盖本插件请求的具体模型，不改变宿主任务配置。体力在模型请求完成后按实际 usage 结算，余额允许透支。

响应性要求：任一时刻只允许一个自主 LLM 请求/Agent 运行在处理决策，避免多个“意志”互相覆盖。能力完成后立即把结果回送同一会话；休息时新事件会提前唤醒原会话，不依赖固定轮询。若新事件在请求或能力执行期间到达，先持久化排队，并在下一个安全的工具往返边界加入同一会话，不另开会话抢占。意外中断按指数退避重新唤起原会话；只有人工停止才保持停止。退避只限制重试频率，不是模型选择的休息，状态与下次尝试时间要在仪表盘中可见。

单次能力执行需要有清晰的超时和完成状态。长时间手机浏览应拆成可续接的工具步骤，在每一步返回观察和状态；不让一个无界工具调用阻塞整个意志会话。卸载时按能力的中断契约取消或等待收尾，外部副作用未确认时记录为结果未知。

## 一次工具往返

```text
持久化会话上下文 + 新观察
  -> 同一意志会话请求 LLM
  -> LLM 返回一个能力调用
  -> 代码校验并记录 step_id / 扣留体力
  -> 能力执行（日记、手机、记忆等）
  -> 持久化能力结果并回送同一会话
  -> LLM 继续决定下一步
```

聊天侧的普通 MaiBot 对话仍独立按原流程工作，不属于意志会话。聊天模型显式提交的兴趣只作为一个事件进入意志会话；不得把普通聊天流或整段聊天历史注入会话。

## 会话状态

| 状态 | 含义 | 结束或转移条件 |
| --- | --- | --- |
| `ACTIVE` | 意志会话正在等待 LLM 决策或执行能力 | 进入停止请求、休息准备、断连恢复或关闭 |
| `REST_REQUESTED` | LLM 已调用 `rest`，请求了休息时长；意志会话尚未停止 | 外层 Agent 正常结束则进入 `RESTING`；若请求/连接异常则按断连恢复，不开始休息计时 |
| `RESTING` | 已调用休息并正常结束会话，正在按麦麦决定的时长休息 | 到达 `rest_until` 后，或新事件提前到达时唤醒同一个逻辑会话 |
| `DISCONNECTED` | 意志运行连接或进程异常中断；状态页显示为“重连等待中” | 按持久化的指数退避时间安排下一次唤起；重试不永久停止 |
| `ENERGY_WAIT` | 旧版本状态；新版本不因体力余额阻断自主模型调用 | 升级后恢复自主会话 |
| `DISABLED` | 插件被停用或正在卸载 | 配置重新启用并完成恢复 |
| `STOP_REQUESTED` | 用户在仪表盘请求会话自行收尾；运行中的当前模型请求仍可能完成 | 模型正常 `finish` 后转为 `STOPPED`；若进程中断则按已明确启动的会话执行断连恢复 |
| `STOPPED` | 用户明确停止后的空闲状态 | 仅由用户从仪表盘重新启动；插件重载不会清除此人工停止标记 |

实现需要区分一次模型 API 响应完成、外层意志 Agent 运行结束、传输失败和进程退出。原始 API 响应的 finish_reason=stop 本身不代表外层运行结束；应以工具调用循环的完成结果为准。整轮运行正常结束时，有有效 rest 请求则进入休息；无人工停止时意外 finish 进入自主恢复等待。超时、网络错误、意外取消、进程退出或未完成的工具调用一律按断连处理。

## 启动、停止与重启恢复

- 插件启用后自动开始自主运行；仪表盘停止操作产生的人工停止标记跨插件重载保留。
- 仪表盘“停止”会向下一次模型决策提供停止请求；模型不应启动新能力并应尽快 `finish`。强制停止会取消当前任务，把未确认的能力和模型用量标记为未知，避免重放副作用。
- `finish` 仅在人工停止请求时结束循环；其他情况下进入自主恢复等待后继续原会话。

- 插件启用后自动创建或恢复 `will_session_id` 并运行唯一意志 Agent，让麦麦自行选择行动或休息。仪表盘重新启动会清除人工停止标记。MaiBot 进程/插件运行器崩溃后重载时，尚未人工停止的 `ACTIVE` 和未提交 `REST_REQUESTED` 按断连策略递增尝试次数，并从持久化 `next_retry_at` 等待；单纯配置热更新只停止/重建监督任务，不应把用量待确认标记改成进程中断的未知状态，也不应增加断连次数。`DISCONNECTED` 保留尝试次数并等待 `next_retry_at`，若已到期则只唤醒一次；`RESTING` 未到期则继续等待，已过期则立即唤醒；旧版体力阻塞状态升级后恢复自主会话。
- 如果进程退出时持久状态为 `REST_REQUESTED`，但没有持久化“外层 Agent 正常停止并提交休息”的完成记录，则无法证明休息已正常开始，应清除待生效请求并按 `DISCONNECTED` 退避恢复。未完成的 `STOP_REQUESTED` 则按用户意图停止，不因重载自动重新启动。
- 重启时若休息截止时间已过，不补跑多次定时任务；只恢复一次，并把期间积压事件合并进同一逻辑会话。
- `DISABLED` 状态只在配置明确启用后恢复；卸载时完整保存上下文和未完成能力状态。

## 休息规则

- LLM 通过 `rest` 能力提交希望休息的时长。运行时代码校验时长并设置硬上限 **12 小时（43,200 秒）**；超出时返回实际接受的时长，LLM 不能覆盖上限。
- `rest` 工具返回代码接受的实际时长，并提示模型结束当前外层 Agent 运行；若模型仍继续调用能力，休息请求保持待生效，倒计时不提前开始。
- 调用 `rest` 只记录待生效的休息请求。只有同一逻辑会话随后使外层 Agent **正常停止**时，运行时才提交休息并设置 `rest_until`。
- 休息计时从会话正常结束时开始，不从工具调用时开始；因此休息期间没有一个仍在后台执行的模型循环。
- 到期后唤醒原 `will_session_id`，恢复其保存的上下文，并加入一条系统观察说明休息已结束及期间排队的事件。
- `rest_until` 使用 UTC 持久化；重启后继续按原到期时间倒计时。仪表盘按当前时间计算剩余时长。
- 休息期间没有正在运行的意志 LLM 或手机/日记能力。普通 MaiBot 聊天照常响应；聊天模型显式调用 `interest.record` 时直接写入记忆或待同步 outbox，不扫描其他聊天内容。需要意志会话处理的兴趣主题和意识会话用户消息会持久化，并提前结束休息唤醒原会话。
- 没有新消息或兴趣事件时，`rest_until` 到期会把同一会话唤醒一次，并将到期观察与积压事件一并交给它。仪表盘“启动”可显式清除人工停止标记并运行会话。

如果休息请求后遇到超时、网络断开、进程退出或工具结果未知，不提交休息；清理未完成的休息请求，标为 `DISCONNECTED` 并恢复原上下文。否则一个尚未正常停止的请求可能意外让 MaiWill 长时间休眠。

## 异常断连恢复

- 外层意志 Agent 异常结束或连接丢失时进入 `DISCONNECTED`；无停止请求时模型错误地选择 `finish` 会进入默认一小时的自主等待，到期后继续同一会话。只有人工停止请求后的 `finish` 才保持 `STOPPED`。
- 保留同一会话 ID、已确认的消息与工具结果、待处理事件和显式运行状态，然后按计划尝试唤起并继续。
- 连续的连接、模型服务和进程异常计入同一个连续重试退避序列，避免外部故障导致紧密调用。间隔按 `min(initial_delay * multiplier^(attempt - 1), max_delay)` 计算；初始间隔、倍增系数和最大间隔可配置，建议默认初始 5 秒、倍增系数 2，最大间隔默认 600 秒（10 分钟）。配置校验要求初始间隔为正、倍增系数大于 1、最大间隔不小于初始间隔。达到上限后继续按上限间隔尝试，不永久放弃恢复。
- 持久化尝试次数、当前退避时长和 `next_retry_at`；重启或收到新事件不能把已排定的退避重置为立即重试。事件在断连期间仍排队，等下一次计划唤起后一起交回原会话。
- 连续失败计数只在会话确实恢复并稳定运行后重置；单次 API 请求成功不单独重置，避免外部异常反复回到最短间隔。稳定运行默认窗口为 60 秒，可通过插件配置调整。
- 退避由代码负责，不可伪装成模型选择的休息，也不能丢弃会话上下文。连接恢复后向同一意志会话提供最近的故障状态。
- 每个能力调用先持久化 `step_id` 和执行状态。重连后已确认完成的能力不重复执行；结果未知的外部操作标记为 `outcome_unknown`，把不确定性交回同一会话判断，不伪造成功或自动重复不可幂等副作用。
- 当会话历史接近模型上下文限制时，可在同一逻辑会话中进行有界上下文整理，保留最近工具往返、未完成事项和关键状态。不要为了压缩历史偷偷启动第二个自主决策会话。

## 仪表盘

仪表盘至少显示：

- 当前状态：活跃、休息中、正在重连、停用；另行显示体力余额（可为负）和未知用量请求数。
- `RESTING` 时显示休息结束的本地时间和实时剩余倒计时，最长显示 12 小时。
- `DISCONNECTED`/重连时显示最近一次断连时间、简短原因和下次重试时间。
- 断连重试时显示当前尝试次数、当前退避间隔和 `next_retry_at`；最大间隔默认 10 分钟，可配置。
- `REST_REQUESTED` 时显示模型提交的休息时长及“等待会话正常结束”，不能提前显示为已进入休息。
- 提供独立的“启动”“停止”“强制停止”操作；停止请求模型自行收尾，强制停止立即中断正在执行的任务。
- 显示待处理事件数量及意志会话最近一次活动时间。

状态和目标时间由后端权威保存；页面用服务端时间基准渲染倒计时，并定期刷新，以免只靠浏览器本地计时而与重启后的状态不一致。仪表盘展示状态，不自行作出意志决策。

## 首版验收场景

1. LLM 在同一意志上下文中依次写日记、使用手机、整理结果；每步结果回到同一 `will_session_id`，没有能力私自启动另一条 LLM 决策链。
2. 一次 LLM API 响应结束后，如果返回工具调用，会话能执行能力并继续同一工具往返；不会误判为断连。
3. 能力完成后立即继续同一会话，不等待轮询；运行中到达的新事件不会并行启动另一个 LLM 决策。空闲时事件立即唤起会话。
4. 会话因连接、服务或进程错误意外中断后，状态变为断连并按指数退避重试；无停止请求时 `finish` 会进入自主等待并继续。默认最大断连间隔为 10 分钟，间隔参数可配置。恢复后保留已完成步骤且不重复副作用。
5. LLM 请求休息并正常结束后进入 `RESTING`；倒计时准确，最长 12 小时，到期恢复同一逻辑会话。
6. 休息请求后若遇到超时或进程退出，不启动休息定时，而按断连恢复。
7. 重启插件或 MaiBot 后，活跃会话上下文、休息到期时间、重试次数、`next_retry_at` 和事件队列都可恢复，不会因重启把退避清零。
8. 插件启用后自动开始探索；`finish` 不会让自主循环永久停下。只有仪表盘明确停止会话才保持停止，且该标记跨重载保留。
9. 重启时未确认提交的 `REST_REQUESTED` 不会误进入休息，而是恢复断连会话。
10. 仪表盘准确显示活跃/断连/休息状态与相应倒计时、体力余额及未知用量提示；休息期间普通 MaiBot 聊天仍正常。
