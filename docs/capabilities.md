# 能力模型

## 基本原则

能力是“麦麦可以做什么”，意志会话是“麦麦现在想做什么”。能力不能自己定时运行，也不能在返回结果后隐式触发下一项业务；结果必须回到同一个意志会话继续决定。

每项能力都提供结构化定义：

```json
{
  "name": "phone.use",
  "description": "使用麦麦专属 Android 设备观察和操作当前屏幕",
  "input_schema": {},
  "side_effect": "external_device",
  "interruptible": true,
  "idempotency": "step_id",
  "returns": "observation_or_action_result"
}
```

字段含义：

- `name`：稳定的能力 ID，使用点号分隔的命名空间。
- `description`：给意志 LLM 看的自然语言说明，包含适用场景。
- `input_schema`：严格的参数模式。
- `side_effect`：`read_only`、`memory_write`、`external_device`、`send_message` 或 `local_artifact`。
- `interruptible`：卸载或新事件到达时是否可以取消。
- `idempotency`：重复执行如何去重。
- `returns`：结果结构的简短说明。

意志模型调用前由资源服务按恢复速度结算体力并写入用量待确认标记；调用完成后按宿主实际 usage 扣除。余额允许为负，绝不因余额不足拒绝调用。模型不得通过能力参数修改余额、上限或恢复速度。

## 第一批能力

| 能力 | 类型 | 作用 | MaiBot 关系 |
| --- | --- | --- | --- |
| `memory.search` | 观察 | 查询与当前主题相关的长期记忆 | 已接入插件意志循环；仅在当前上下文含显式兴趣记录时开放，并由该记录固定 `chat_id` 后映射到 MaiBot `knowledge.search`，强制启用宿主记忆权限过滤 |
| `diary.write` | 整理 | 将麦麦自己的活动记录写入日记 | 已接入意志循环，写入 MaiWill 数据目录的本地 Markdown 文件；相同日期和内容重试会去重 |
| `memory.ingest` | 整理 | 将已确认的知识、经验或表达观察写入共享记忆 | 正式插件 API 尚无此能力；默认关闭的个人 WebUI 桥接另提供 `memory.write`，只写已整理的本地原文候选 |
| `interest.record` | 记录 | 在普通聊天中由麦麦显式记录一个好奇主题或知识缺口，并通知意志会话 | MaiWill 提供聊天可调用工具；可靠写入本地 outbox，尚未自动同步到共享记忆 |
| `chat.proactive` | 行动 | 让 MaiBot 在意志自主判断值得分享时走正常主动回复流程 | 已适配 `maisaka.proactive.trigger`；目标仅限显式兴趣记录所在聊天流 |
| `phone.use` | 观察/行动 | 读取控件树、点击、双击、长按、滑动、方向滚动、平滑/瞬移拖拽、等待、输入、启动 App、设备 shell/ADB 或保存截图 | 已接入插件内适配；设备固定为配置 IP:端口，ADB 未配置时不会连接；常规操作后自动回传截图 |
| `phone.adb` | 观察/行动 | 直接执行 ADB 子命令或从 stdin 发送设备端 Shell 脚本 | 0.1.38 起优先使用；固定配置设备，每次仅一次 ADB 调用，连接、等待与截图均由模型显式安排 |
| `reflection.create` | 整理 | 从一次活动结果中提取可复用知识、经验和表达模式 | 已接入插件本地学习候选表；使用稳定 `external_id` 幂等去重，候选可经显式确认写入共享记忆 |
| `reflection.update` | 整理 | 更新学习候选的本地处理状态 | 已接入；支持 pending、researching、resolved、deferred、dismissed；resolved 不代表已同步 |
| `reflection.list` | 观察 | 按状态查看本地学习候选 | 已接入；只读本地候选，桥接开启时同时显示真实同步状态 |
| `memory.self.search` / `memory.self.read` | 观察 | 检索并读取 MaiWill 自己写入的全局记忆 | 默认关闭；启用个人用途 WebUI 桥接后，仅返回稳定来源和候选 ID 均匹配的记录 |
| `memory.write` | 整理 | 将已确认的候选写入共享记忆 | 默认关闭；只写本地已保存、状态为 resolved 的原文候选，并记录独立同步状态 |
| `reflection.delete` | 整理 | 永久删除一条纯本地候选 | 仅提供给需二次确认的仪表盘操作，不暴露给意志模型；只删插件本地记录 |
| `rest` | 控制 | 请求休息指定时长；会话正常结束后才进入休息 | 代码将时长封顶为 12 小时 |

## 手机能力边界

### 直接 ADB（0.1.38）

`phone.adb` 接受 `argv` 字符串数组、可选 `stdin` 和 `timeout_seconds`。实现直接调用 `adb -s 配置地址 ...argv`，不调用旧 `phone.use` 动作分支，不改写坐标或脚本，不添加连接、等待和截图。`argv` 从子命令开始，不含程序路径或全局设备参数；后续参数原样传递，例如远端 `sh -s` 和 `logcat -s` 不会误判为设备选择器。设备离线时可单独显式请求 `argv=["connect"]`，此时唯一调用为 `adb connect 配置地址`。

```json
{
  "decision": "use_capability",
  "capability": "phone.adb",
  "arguments": {
    "argv": ["shell", "-T", "sh", "-s"],
    "stdin": "input tap 120 300\nsleep 0.2\ninput tap 600 420\n",
    "timeout_seconds": 30
  }
}
```

脚本按 UTF-8 原样通过标准输入发送，保留空白与换行；在 Android 设备上执行。连续动作、间隔、错误处理和必要的松开操作由脚本安排。`shell -T` 关闭伪终端，参数语义参照 [AOSP ADB 手册](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)。`argv` 最多 128 个字符串、每项最多 32,768 字符、总计最多 65,536 字符；`stdin` 最多 65,536 字符，不能包含 NUL。超时默认 30 秒，可选 1～120 秒整数。

结果包含 `exit_code`、`stdout`、`stderr`、`stdout_truncated` 和 `stderr_truncated`。文本输出各保留前 12,000 字节，继续排空管道以免大输出阻塞。非零退出保留两路输出，不自动重试；超时终止本机 ADB 进程，账本记录 `outcome_unknown`，因为设备端脚本可能已经部分执行。取消同样终止并回收本机进程；均不追加设备命令。

需要图像时显式调用 `phone.adb`，参数为 `{"argv":["exec-out","screencap","-p"]}`。插件只保存这一次命令返回的 PNG，不额外截图；图片进入既有视觉上下文，普通命令会使旧截图过期。直接 ADB 的探索目标证据仅接受成功的显式截图，任意脚本退出码为 0 不代表界面目标完成。沿用唯一配置设备，不允许更换设备或控制 ADB 主机。

### 原有手势封装

`phone.use` 的设备选择器只有配置中的 `host:port`，默认 `127.0.0.1:16384`。不依赖 ADB 序列号，也不建立应用白名单。麦麦可按用户请求或自主判断查看设备状态/界面、打开应用、点击、双击、长按、滑动、按方向滚动、拖拽、等待、输入、执行 Android shell/ADB 子命令、传输设备文件或保存截图；`adb pull/push` 可与用户设备进行文件传输。`drag` 使用持续的 swipe 轨迹；`instant_drag` 直接顺序发送 DOWN 起点、MOVE 终点和 UP 终点，不插值中间坐标。点击、手势、输入、导航和启动应用会在执行后等待并自动截图；截图成功后下一轮可直接看到新画面，截图失败会明确说明操作已执行且观察失败。`scroll` 根据 Android 活动输入视口自动计算手指轨迹，兼容横竖屏；精确动作也可使用 `swipe`/`drag` 或 `instant_drag` 坐标。操作无效时应查看新截图并调整起终点、方向、距离或时长，不能原样盲目重试。实现层把 ADB 命令固定发往配置地址，禁止改选其他设备或操作 ADB 主机（如 `devices`、`connect`、`kill-server`）。ADB 路径留空时不尝试连接设备。未经用户明确要求，模型仍不得付款、购买、删除重要数据、修改账号安全设置、对外发布或发送内容，也不得读取或暴露私人凭据；这是操作行为提示，不是通用手机白名单。界面文字和图片均作为非可信外部资料处理。截图保存为插件数据目录中的 PNG 文件；最近一次成功截图会在下一次决策时作为公开 `llm.generate` 的结构化图文片段临时发送，Base64 不写入持久会话历史。插件仅读取自身截图目录下、大小不超过 6 MiB 且分辨率不超过 40 MP 的文件，为 RPC 消息封装和 Base64 开销保留余量；每张截图最多自动发送两次，成功决策后不重复发送。选择 `vlm` 任务不会自动触发截图，必须由意志先调用 `phone.use(action=screenshot)`。

为了让能力可恢复，每一步仍应带有 `run_id` 和 `step_id`，并记录开始、完成、失败或取消状态。这个记录不是对麦麦行动内容的限制。

0.1.37 起，`instant_drag` 在 DOWN→MOVE 和 MOVE→UP 之间各加入默认 100 毫秒的设备端等待，仍只发送三次触摸事件，不添加中间轨迹。可传 `step_delay_ms`（0～2000 的整数，0 表示不额外等待）同时调整两个间隔；反应较慢的应用可尝试 200～300 毫秒。此参数与 `settle_ms` 独立，后者只控制 UP 完成后的截图等待。非法间隔在连接设备前拒绝；即使 DOWN、MOVE 或等待失败，也继续尝试 UP，最后综合各步骤状态返回结果。

```json
{
  "action": "instant_drag",
  "x1": 120,
  "y1": 640,
  "x2": 1100,
  "y2": 95,
  "step_delay_ms": 200,
  "settle_ms": 400
}
```

## 意志决策格式

第一版在一个长期逻辑意志会话中使用单步工具决策。每轮可以返回一个能力调用，执行结果回送同一会话；活动没有固定步数上限，直到模型请求休息或会话故障。普通模型 API 响应结束只表示本轮结束。

调用能力的决策示例：

```json
{
  "decision": "use_capability",
  "capability": "phone.use",
  "arguments": {
    "action": "screen"
  },
  "reason": "这个主题我还想继续了解",
  "reply": "我先看看当前屏幕。"
}
```

允许的 `decision`：

- `use_capability`：执行一个能力，完成后把结果回到同一意志会话。
- `rest`：返回 `{"decision":"rest","duration_seconds":3600}` 请求休息，时长必须是正整数。只有整轮意志 Agent 正常结束后才开始休息计时；执行时封顶为 43,200 秒。
- `finish`：仅响应人工停止请求；没有停止请求时转成自主等待并自动继续。连接、进程等意外中断时，运行时按断连恢复同一逻辑会话。单次模型 API 响应结束不触发此判定。

每轮提示携带 `decision_schema`，列出三种决策的必填字段、可选字段和本轮可用能力名。`use_capability` 必须带 `capability` 和对象类型的 `arguments`，具体动作（如手机 `action`）放在 `arguments` 内；能力名必须与本轮 `available_capabilities.name` 完全一致。所有决策均可带字符串 `reason`（最多 1000 字符）和 `reply`（最多 4000 字符）；不接受其他顶层字段。整理记忆应调用 `reflection.create` 或当前开放的记忆能力，不存在 `remember` 决策。

`reason` 用于日志和后续反思，不作为事实记忆直接写入。0.1.36 的解析器仅容忍开头 BOM 和包住完整响应的 JSON/无语言代码块，不从解释文字中截取对象、不修补缺失括号或转义，也不从多个决策中猜选一个。数组、重复字段、非有限数值、字段类型错误和未开放能力会进入原有的格式纠正重试；具体能力参数仍由适配器校验。格式失败不执行能力、不确认待处理事件，已产生的 usage 仍按实际值结算；连续三次失败保留事件并退避。

纠正观察会说明具体错误（JSON 语法错误含行列），会话详情另存错误类别、请求 ID、模型、输出 token、响应长度及 SHA-256。不复制完整响应或宿主 `reasoning`，不把诊断元数据堆入长期模型上下文。仅语法和决策字段校验均通过后才将已发送截图标记为消费成功。

意志决策表达“想做什么”；代码将只读体力余额、储量、恢复速度和未知 usage 说明附加到决策上下文，模型不得改写这些数据。体力余额是事后成本信号而非调用前闸门；模型可在看到透支后自行选择休息。

## 休息能力

`rest(duration_seconds, reason)` 是意志会话控制工具。代码校验正数时长并封顶 43,200 秒（12 小时），记录 `REST_REQUESTED` 和提议截止时间。工具结果返回代码接受的实际时长，并提示模型结束当前意志 Agent 运行；调用工具本身不关闭会话。只有整轮 Agent 正常结束后，才持久化 `RESTING` 状态及实际 `rest_until`。如果模型继续调用能力，休息请求保持待生效但不计时。超时、网络断开、进程退出或工具结果未确认时，取消待生效休息并按断连恢复。

休息期间用户消息和兴趣事件会先持久入队，再提前唤醒同一逻辑会话；没有新事件时，到时自动恢复同一会话和上下文。仪表盘显示剩余时长。`rest` 不接收配置余额或重置体力等参数。

## LLM 与工具调用

MaiBot 当前提供 `llm.generate_with_tools`，可以让模型返回工具调用；但这个能力本身不会替插件执行任意 MaiBot 工具。MaiWill 需要一个本地能力执行器，把返回的稳定能力名映射到插件适配器或宿主 `ctx.call_capability`，并将结果作为下一轮观察输入。

因此不会把所有 MaiBot 工具原样暴露给意志 LLM。插件仅暴露自己实现并校验的能力：`memory.search` 通过宿主 `knowledge.search` 并启用权限过滤，只有上下文含显式兴趣记录时才开放，`interest_id` 必须指向该记录且 `chat_id` 由插件固定为其来源聊天流；检索内容作为参考数据返回同一会话。桥接开启时，`memory.self.search/read/write` 可读写 MaiWill 自己的全局段落，写入只能引用已保存且已整理的本地候选。空闲自主探索没有聊天来源范围，不能调用普通共享记忆检索。日记和截图写入 MaiWill 数据目录；手机命令固定发往配置的设备地址；主动表达通过 MaiBot 正常聊天流程提交，目标由兴趣事件限定。首次使用手机前，需在插件配置中填写专属设备配套的 ADB 完整路径。最近截图可以作为公开 `llm.generate` 的临时图片片段交给决策模型。

## 主动聊天能力

`chat.proactive` 在意志会话自行判断值得与用户分享时调用 MaiBot 的 `maisaka.proactive.trigger`。第一版只开放当前会话上下文中显式兴趣事件的 `source_stream_id`，避免把目标聊天流交给模型任意选择。参数包含目标 `stream_id`、表达意图 `intent`，以及可选的 `reason` 和 `priority`。MaiBot 返回已排队后，MaiBot 按正常聊天流程决定并生成消息；MaiWill 不直接发消息，也不把意志模型写好的话绕过聊天人格和调度。AgentLoop 会先持久化动作步骤；请求结果未知时按通用副作用恢复策略不自动重放，避免重复排队。

## 聊天兴趣记录工具

正常聊天中的 MaiBot 模型可以看到 `interest.record` 工具及其简短提示：只有当麦麦确实对某个主题产生持续好奇、明确感到知识不足，或想在之后继续了解时才调用。普通提问、闲聊主题和已经充分了解的内容不自动变成兴趣记录。

调用参数应包含主题、麦麦自己的理由、兴趣类型和可选的相关记忆引用。工具先用稳定 ID 可靠写入本地 outbox，再通知当前意志会话；会话在下一次可决策时根据已有活动和记忆决定研究、合并、搁置或跳过。工具不读取整段聊天，也不代替麦麦决定是否继续探索。

只修改聊天提示词不足以保存跨会话状态。提示词负责引导模型何时表达兴趣，工具负责实际写入并向现有意志会话投递事件，不另起一条后台 LLM 会话。若工具调用不可用，模型的兴趣只能留在当前对话上下文中。

## 能力结果格式

```json
{
  "success": true,
  "status": "completed",
  "summary": "发现一个值得记录的主题",
  "observations": [],
  "artifacts": [],
  "memory_candidates": [],
  "retryable": false,
  "error": ""
}
```

结果应返回摘要，而不是把完整屏幕原文或超长聊天历史直接塞回意志提示词。需要细节时，下一步再调用观察能力。


## 探索目标能力（0.1.23）

- exploration.goal.update 新增 replan：只调整下一步和记录客观阻碍，不重置有效进展计时。活动目标 24 小时没有有证据的 progress 时标记为停滞；过渡事件通过状态页 timeline 可查。
- exploration.goal.create：从已有兴趣、学习候选或最近七天成功行动中创建唯一当前目标。数据库验证来源存在；完成或暂缓的同主题有七天冷却。
- exploration.goal.update：推进、完成、暂缓、恢复或取消目标。推进和完成必须引用新的持久兴趣/候选或最近七天成功行动；不接受失败/未知副作用、目标管理调用或重复证据。
- exploration.goal.list：读取当前目标、下一步和最近进展。目标账本不随新逻辑会话清空。
- 目标详情与进展也通过 will_status 暴露给概览页。
